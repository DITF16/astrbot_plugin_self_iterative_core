## 📖 简介 | Introduction

**Self-Iterative Core**(下文简称**自迭代核心**) 是一个为 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 设计的高级插件。是可以创建、修改插件的插件。

本插件**允许 Bot 在一定范围内完善、修改、升级自身已有的功能，或者按照用户要求创造新功能，逐渐进行自我完善与进化**。它旨在探索 LLM (大语言模型) 在代码生成、自我修正及逻辑迭代方面的潜力，为您带来前所未有的智能体养成体验。

## ✨ 核心特点 | Features

### 🛡️ 插件修改更安全

- 修改、批量写入和卸载其他插件前自动创建备份。
- 支持查看备份历史、按备份回滚，以及在回滚前保留当前状态。
- 写入已有文件前校验文件哈希，减少覆盖其他修改的风险。
- 插件加载失败时可以按指定备份恢复并重新加载。

### 🧠 插件编写更省心

- 内置整理好的 AstrBot 插件开发知识库，覆盖插件配置、事件指令、消息处理、消息发送、LLM、工具、会话、存储、渲染、平台适配和 HTTP 接口等内容。
- 开发前可按主题检索资料，读取关联知识，并记录适用版本和验证状态。
- 知识库会随插件版本更新；运行时补充的内容和本地修订会保留。
- 可在 AstrBot WebUI 的插件页面中查看、修改、归档知识条目。

### 📚 插件错误不再重复

- 工具执行失败会自动记录为待验证错误经验。
- 修复并实际验证后，可以将原因、处理方式和验证结果写回经验库。
- 后续开发会优先检索已有错误经验，减少重复踩坑。
- 知识正文和索引支持修订号校验，避免旧内容覆盖新修改。

### 🤖 模型选择更灵活

- 可以从 AstrBot 已配置的模型提供商中选择用于插件编写的模型。
- 留空时跟随当前会话模型。
- 模型的代码理解、推理和调试能力会影响插件编写质量。

### 🧩 Agent 编排与工具执行

- 采用“Agent 负责规划、LLM Tool 负责执行”的方式：Agent 拆分开发任务、检索知识并安排步骤，具体读取、备份、写入、加载、测试和回滚都由受控工具完成。
- 简单任务可以由主 Agent 直接调用工具；复杂任务再进入开发编排流程，避免不必要的多 Agent 调用。
- 插件行为测试复用 AstrBot 已加载的实时插件实例，不直接导入插件源码，减少测试环境与实际运行环境不一致的问题。

### 💬 开发任务插话

- 没有活动开发任务时，消息完全按 AstrBot 正常对话处理，不进行额外分类。
- 开发任务运行期间，任务补充会进入插话队列，在当前工具步骤结束后处理。
- 支持通过“暂停任务”“继续任务”“停止任务”控制当前开发任务，也可以发送“再加一个配置项”“补充某项功能”等临时要求。
- 插话只在安全的工具步骤边界处理；文件写入、插件加载等操作不会被强行中断，以避免留下不完整修改。

## 🚨 市场发布规范 | Market Publishing Rules

> [!IMPORTANT]
> **严禁将未审查的 AI 生成代码直接提交至插件市场！**

如果您计划将使用本插件生成的代码/插件发布到 AstrBot 插件市场，**必须** 遵循以下规范：

1.  **必须经过人工审查**：生成的代码必须经过您的人工阅读和测试，确保无恶意逻辑、无明显 BUG。
2.  **功能稳定性**：确保插件在正常环境下运行稳定，不会导致宿主 Bot 崩溃。
3.  **符合异步规范**：AstrBot 基于异步架构，请务必检查生成的代码是否正确使用了 `async/await`，禁止在主线程中执行阻塞操作。
4.  **禁止垃圾搬运**：禁止生成后不经审查直接发布。这会给仓库维护者和代码审查人员造成巨大的无效工作压力。**违者后果自负。**

## 🛠️ 安装与使用 | Installation & Usage

1.  **安装插件**：
    *   通过 **AstrBot 插件市场** 直接安装。
2.  **模型检查**：
    *   选择适合代码理解和调试的模型；模型能力会影响插件编写质量。

> [!TIP]
> **如何让修改实时生效？**
>
> 想要自迭代核心修改的功能可以实时生效，**必须开启 AstrBot 的插件热重载机制**。
> 请通过设置环境变量 `ASTRBOT_RELOAD=1` 来启动 AstrBot 主体。
